# АГРОСЕМ — Трактори B

У GitHub-репозиторії актуальний код розміщено в корені, а оригінальні PDF і Excel — у `inputs/`. Команди запуску для репозиторію наведено в [головному README](../README.md). Опис `code/` і команди нижче стосуються окремого ZIP-пакета.

Пакет містить детальний командний план і виконану першу з п’яти командних частин: підготовку даних, аудит і сегментацію. П’ять ролей не змінюють трьох оцінюваних завдань PDF.

Почніть із цих файлів:

1. **01_План_і_ролі.docx** — вимоги, план на п’ять робочих днів, п’ять ролей, залежності, вихідні таблиці й критерії готовності.
2. **02_Частина_1_аудит.docx** — виконаний аналіз першого учасника, перевірені числа, графіки, обмеження та передача роботи.
3. **03_АГРОСЕМ_B_дані_та_аудит.xlsx** — 26 аркушів з усіма 13 398 SKU, історією, сегментами, аудитом і словником.
4. **data/** — CSV для команди; **charts/** — ілюстрації; **code/** — код відтворення.

Вихідні PDF і Excel не змінювалися й не включені до архіву: використайте надані оригінали. Текстові версії звітів доступні у Markdown.

Важливі умови читання:

- Історичний зріз прийнято на 12.11.2024. Повна історія: 2021-11 — 2024-10. Поточний листопад 2024 неповний і відділений.
- NaN залишено невідомими значеннями. Два SKU зовсім не мають історії повних місяців і не зараховані до нульового попиту.
- «Сума хітів = 3» не доводить трьох унікальних клієнтів року.
- Грошові суми — оцінка за поточним прайсом; валюта й тип ціни не вказані.
- Рівень сервісу і COEFF — різні величини. Оптимальні замовлення належать до наступних командних частин.

CSV у data/ мають кодування UTF-8 з BOM, роздільник `;` і десяткову крапку. `monthly_long.csv.gz` — стиснений довгий формат із комою як роздільником для програмного аналізу. Первинний ключ — sku_id; для історії — sku_id + month.

Відтворення на Python 3.11 у PowerShell після розпакування:

```powershell
python -m pip install -r .\code\requirements-agrosem.txt
python .\code\build_agrosem_analysis.py --source 'C:\шлях\12_11_2024_140029.xlsx' --case 'C:\шлях\АГРОСЕМ_case.pdf' --output .\regenerated_results
```

`build_agrosem_analysis.py` і `agrosem_report_content.py` мають бути в одній папці. Скрипт за замовчуванням читає вихідний Excel заново; кеш не потрібний. Він відтворює числовий аналіз і звіти саме наданого історичного зрізу. Для нового набору потрібно також адаптувати описові шаблони та перевірити календарну прив’язку.

`manifest.json` фіксує SHA-256 оригіналів і розміри таблиць. `validation_summary.json` містить незалежну перевірку файлів. У листі «Аудит» 18 перевірок пройдено, три питання первинних даних позначено REVIEW: невідомий CC 0; три випадки хітів без продажів у одного SKU; 72 співвідношення резерву й доступного залишку, що потребують уточнення семантики.

Перевірку можна повторити з папки розпакованого пакета:

```powershell
python .\code\verify_agrosem_outputs.py --output . --source 'C:\шлях\12_11_2024_140029.xlsx'
```

Параметр `--source` додатково порівнює всі 482 328 комірок історії продажів і всі 482 328 комірок історії хітів із джерелом, включно з пропусками.

Перший учасник передає базу учаснику 2 для прогнозу, учаснику 3 для сервісу та Cu/Co, учаснику 4 для запасів і бюджету, учаснику 5 для незалежної перевірки та захисту.
